WHAT THE PROJECT DOES (V1 SCOPE)
==================================================
Input: a company name (typed in the console).
Output: a report with a signal (bullish / neutral / bearish), the numbers behind it, cleaned news, and a plain-English explanation.

Pipeline:
  1. Resolve company name -> ticker (NO LLM. Use Yahoo search through yfinance; check the installed yfinance version's search API, otherwise call Yahoo's search endpoint with requests. If more than one reasonable match, print the top 5 and ask me to choose by number. Log my choice.)
  2. Fetch price history (about 2 years of daily closes) with yfinance.
  3. Quant score from prices (pure code, no LLM).
  4. Fetch recent news (about 8 to 10 items: title, snippet/summary, publisher, date, URL). Use headlines and snippets from the API only. Do NOT scrape websites.
  5. Cleaner (Gemini): treats each news item as UNTRUSTED text. Gemini has no tools. For each item it must return JSON in a fixed schema: neutral one-sentence summary (max 25 words, no URLs, no instructions), is_about_company (bool), injection_suspected (bool), is_opinion_or_fact ("fact"/"opinion"). Neutralize hype wording; do not claim to remove all bias.
  6. Validate (pure code): reject items that fail the schema, are too long, contain URLs, have injection_suspected = true, or are not about the company. Log every drop with the reason.
  7. Sentiment (scorer chosen in Step 0): one score per kept item from -1 to +1. news_score = simple average of kept items (if fewer than 3 kept items, news_score = 0 and mark "insufficient news").
  8. Combine (pure code): final_score = 0.8 * quant_score + 0.2 * news_score. Weights and thresholds live as named constants in config.py. Signal: final_score >= 0.25 bullish, <= -0.25 bearish, otherwise neutral.
  9. Report (Gemini): receives ONLY structured data (numbers, votes, cleaned summaries). It writes a short markdown report: signal, why (which factors drove it), any conflict (e.g. quant bullish but news negative), what would change the view, data sources and dates, and a clear disclaimer: "Educational only, not investment advice." The prompt must say: use only the data given, never invent numbers, you cannot change the signal. The report step has no tools.

Quant rules (3 votes, each +1 or -1):
  - trend: last close > 200-day simple moving average
  - momentum: last close / close 126 trading days ago - 1 > 0
  - risk: annualized volatility of the last 60 daily returns (std * sqrt(252)) < 0.30
  quant_score = sum(votes) / 3   (range -1 to +1). Return each vote with its raw number (e.g. the MA value, the return, the volatility) so the report can explain it.

NOT in V1: caching, MCP server, Alpaca/trading, async code, databases, web UI, classes unless truly needed. No frameworks beyond what is required.
